# 文章语料写作契约

本目录是站点 300 篇打字练习正文的**唯一来源**。`scripts/generate-articles.mjs` 读取这里的
`short.mjs`、`medium.mjs`、`long.mjs`、`water.mjs`，校验后写出 `public/data/articles-*.json`
与 `public/data/articles-index.json`。整体重写的正文基线版本为 3，后续按篇维护版本。

## 事实与版本维护

正文是虚构的打字练习场景。人物、商店、书刊、现场记录与测量数字用于叙事，不是实际调查、
科研实验或临床结果；涉及通用科普、技术、历史和医疗知识时，仍须核对可靠原始资料，
不能用虚构读数证明普遍规律。第一轮逐篇问题、处理依据和核实来源见
`docs/article-review-round1.md` 与对应 JSON 记录；内容密度和篇幅审读见
`docs/article-review-round2.md` 与对应 JSON 记录；自然度与整库差异审读见
`docs/article-review-round3.md` 与对应 JSON 记录。

正文相对当前已发布版本发生变化时，在该篇源对象中显式设置 `version` 为基线版本加一；
未改正文的篇目保留原版本。基线为 3 的旧对象可省略该字段，生成脚本按 3 读取。
同一批未发布修订中的反复编辑和重复生成均不再加版本；下一次发布后以新基线继续递增。
不要把四组文章整体升版，也不要因生成而重置已存在的逐篇版本。

## 为什么要重写

上一版正文由模板槽位拼装：12 个开头 × 12 个转折 × 12 个收尾按序号轮转，中间用抽象名词填空。
诊断结果（对旧 300 篇统计）：

- 548 个整句跨篇复用，单句最多同时出现在 15 篇里，例如“眼不见心不烦这话，在这儿不管用”“没什么惊天动地的结论”；
- 15 篇共用“谁也没多说，可谁都盼着它能自己好起来”，18 篇共用“挑了个平常的日子复查，能再次出现的改善才算数”；
- 结尾清一色格言式感悟（“道理不新鲜，做到不容易”“仅此而已”“如果只能留一句话”）；
- 长文平均 20 段、段长标准差仅 15 字，段落长度几乎相等，读起来像把同一篇作文拆碎洗牌；
- “真正”出现在 89 篇（30%），“反而”63 篇（21%），“不是……而是”58 篇（19%）；
- 全文几乎没有人名、地名、价格、次数、对话，读完什么信息都没留下。

所以正文改为人工写作，模板机器整体删除。**不要**用循环、占位符或句式池重新生成这些文字。

## 硬性规则

1. **细节服务内容。** 每个时间、数量、价格、位置、物品和动作都应推进事件、解释现象、
   刻画人物或为后文提供必要信息。不要为制造真实感添加无关数字，也不要删掉有作用的生活细节。
2. **对话有用途。** 引语应呈现分歧、传递信息或推动回应；可以改用简洁的间接叙述，也可以没有引语。
   使用引语时用中文引号 `“”`，不设每篇最低数量。
3. **结尾由内容决定。** 可以停在对话、画面、事件后果或尚未解决的问题，也可以给出材料支持的
   判断、机制解释和个人思考。不要求悬而未决或停在小动作上；禁止脱离具体内容的格言、劝诫和
   对仗总结，继续避免“才是最重要的”“更值得”“本身就是”这类空泛点题。
4. **叙述者不要统一。** 可以用“我”，可以用分配表给的称呼，也可以不出现叙述者。同一批里
   “我们”最多 1 篇。
5. **句子随意思展开。** 按内容安排长短，不强制出现八字以下或三十五字以上的句子，
   不为过校验拆出无意义短句或拼接冗长复句。
6. **段落各有进展。** 根据事件、解释、分歧或后果分段，不设段数和最长最短段的比例。
   长文删后不足长度时补充与主题直接相关的过程，不能靠换时间、换地点和重复记录凑长度。
7. **按题材和内容选择形态。** 分配表的形态是写作参考，不是需要补齐的情节步骤。
   科普要解释现象与机制，随笔可以思考，职场文字要呈现任务与分歧，群聊要有回应和不同立场。
   不要把每篇都写成“遇到问题—记下一串数字—换个办法—停在小动作上”；结论和未完成都可以自然出现。
8. **正文使用汉字、中文标点和年份中的半角数字。** 年份使用四位阿拉伯数字
   （“2026年”，档案名称中的年份也写作“2026”）；其他数字、百分比仍写汉字
   （“三十二”“百分之八十五”）。不得出现 ASCII 字母或 ASCII 标点；
   不得出现连续标点（`，。`、`？？` 这类）；
   引号必须成对。
9. **长度**（去掉全部空白字符后的字符数，含标点）：
   | 长度 | 区间 | 目标 |
   | --- | --- | --- |
   | short | 80–180 | 145 左右 |
   | medium | 300–600 | 470 左右 |
   | long | 1000–1800 | 1300 左右 |
   | water | 400–900 | 620 左右 |
10. **篇内不得重复。** 不得出现相同整句（8 字以上），同一段 12 字以上文字不得重复 3 次。
11. **不要搬别的篇目的句子。** 开头和结尾最容易撞车：写之前先想清楚这篇的切入点是什么。
12. 阅读随笔可以讨论书、语言和阅读经验，叙述仍须有具体依据。不要跳出正文向练习者解释
   这篇文章怎么写、为什么这样写，也不要借写作或阅读之名填充泛泛的评语。

## 黑名单

**生成脚本会直接报错的固定串**（不要写）：

```
道理不新鲜 说到底 仅此而已 不敢打包票 如果只能留一句话 眼不见心不烦 没什么惊天动地的结论
才是最重要的 更值得 本身就是一种 这次的经历 这次经历 由此可见 总的来说 在某种程度上
从某种意义上 不可否认 与此同时 值得注意的是 不难发现 可以看出 归根结底 换言之 换句话说
需要指出的是 日子照常 事情不大 眼不见为净
```

**每篇合计不超过 2 次**：其实、真正、反而、值得、往往、毕竟、或许、无疑、某种程度上。

**逐篇审读的句式提醒**：不要用“让……变得……”“让……重新……”等句式制造抽象升华，
但“搬开箱子，让抽屉重新拉得开”描述的是具体动作与结果，可以使用；不能仅凭这些词判为空话。
`不是……而是……` 全篇最多 1 次，且不得出现在结尾句。

## 形态参考（按内容选择，不循环套用）

| 代号 | 形态 | 说明 |
| --- | --- | --- |
| S1 | 现场白描 | 从一个具体动作或物品切入，不先给结论，全文把这件事写清楚 |
| S2 | 对话推进 | 用两三个人的对话写出分歧，叙述只做串联 |
| S3 | 时间线 | 按“某天—某天—后来”推进，写出过程与中间的反复 |
| S4 | 失败复盘 | 先写没成的那一次，再写第二次改了什么 |
| S5 | 两种做法对比 | 同一件事的两种做法并排写，判断须有内容支持 |
| S6 | 连续观察 | 记一段时间里的次数、时间、数字，让规律自己浮出来 |
| S7 | 步骤清单 | 把做法分步写出来，中途插一次意外 |
| S8 | 一问一答 | 有人问、有人答，再加一次追问 |
| S9 | 事后回访 | 过一段时间回头看，写清变化及其对人物的影响 |
| S10 | 现场分歧 | 一件小摩擦，各人立场不同，最后怎么落地 |
| S11 | 数字对账 | 从一个对不上的数字开始，一直查到对得上 |
| S12 | 开放收尾 | 问题尚未解决时自然保留空缺，不人为拖住已经发生的结果 |

## 范例

下面是**参考写法**，不要照抄内容，也不要把它当模板批量改写。

short（一到四段，150 字上下，停在一句引语上）：

> 打印机的出纸口又吐出半截表格。老陈把纸抽出来对着光看了看，没说话，翻开机盖把里面那沓又抖了一遍，还是少。第三次了，每次都得打三页以上。他给维修打电话，对方说下午来。下午来的是个年轻人，拆开侧盖，从进纸轮底下拈出一小片标签纸，上个月贴快递单时掉的。老陈盯着那片纸问：“就这东西？”年轻人说：“就这东西。”

medium（四段，段落长短不均，停在具体动作上）：

> 六月里，小林连着三天没找到那份报价单。文件名从“最终版”到“最终版二”，再到“真的最终版”，修改时间只差几分钟。
>
> 他去问负责归档的老周。老周把屏幕转过来，文件夹里躺着七份同名文件。“你发给客户的是哪一份？”老周问。小林答不上来。
>
> 两个人花了一个下午逐份比对金额，最后从下载目录里翻出发出去的那一份：总价比其余六份少两千八百块，是客户压过价的版本，另外六份都还留着旧价。
>
> 老周没让他装文件管理软件，只定了一条：文件名照“2026年七月二十六日青禾报价单”这样写，日期在前，项目在后，不许出现“最新”两个字。小林当天把七份删到一份。第二天早上他打开文件夹，直接点开了最上面那一份。

long 的写法：按主题需要展开过程、解释、分歧或后果，每段带来新的进展。
失败、改动和不同意见是可选的展开方式，不要求换满几个时间或场景；结尾与全文的内容相称。

water（群聊答疑，回应应带来新信息；段数、引语数量和收尾方式按内容安排）：

> 群里有人发了一张厨房秤的照片，说买回来的青菜少了差不多一两。底下立刻跳出来三种说法：秤不准、袋子含水、摊主手快。
>
> “你先换个东西称。”开超市的老魏回得最快，“拿一包没开封的盐，包装上写着多少就称多少。”

## 交付格式

每批的分配表在 `_parts/` 下。写完后把结果写成**一个 JSON 文件**，路径和文件名以分配表为准，
结构固定为：

```json
[
  { "id": "short-001", "title": "没有行动项的会议", "topic": "职场办公", "length": "short", "text": "第一段。\n\n第二段。" }
]
```

- `text` 里段落之间用 `\n\n`，不要有行首缩进，不要用 Markdown 标记。
- `title` 不超过 14 字，只用汉字，篇目之间不得重复。
- 写完必须自查长度：

```bash
node -e "const a=require('./scripts/article-corpus/_parts/s01.json');for(const x of a)console.log(x.id,x.title,x.text.replace(/\s/g,'').length)"
```

长度不在区间内或命中黑名单的，当场改掉再交。篇数、ID、主题、长度、中文字符与标点、
唯一性及篇内跨篇重复度约束仍由生成器和测试检查；形式配额取消不等于取消编辑质量要求。

## 最后一道自查

通读每一篇，把里面所有具体信息（时间、数字、名字、物品、谁说了什么）删掉，如果剩下的句子
放到任何一篇文章里都成立，那就删掉这句话——那正是“AI 味”的来源。

## 第二轮规则调整依据

原规则把具体数量、引语、极短与长句、段数及段长比例当成每篇必备项，实际造成了
“跟风没关系”“他停下来”等孤立补句，以及只为达到句长而拼接的句子。
第二轮取消这些最低配额，生成器与文风测试同步取消；必要的数据和重复度约束维持原值。
审读仍需逐句说明细节的作用，并检查时间线、数量与因果，不能以自动检查通过代替通读。

中篇第二十七篇的“让衣柜抽屉重新拉得开”也被旧的抽象使动正则误判。
第二轮取消该宽泛正则，保留已列出的空话固定串和副词限制；抽象升华由逐句审读判定。

## 第三轮规则调整依据

本轮编辑前的横向比较显示，各题材的末段反复出现“先核对、留记录、暂不下判断”，群聊三十篇末段
全含否定表达。原来的“结尾不许升华”、强制停在事件以及形态中的“不下判断、不做总结”，
把防止空泛说教扩大成了排斥有依据的结论。本轮改为按内容选择结尾，允许有限判断、机制解释
和具体阅读思考；不新增结尾类别配额，也不把全部篇目改成结论句。

生成器原本只检查固定空话和数据契约，并未要求动作或开放收尾，因此维持这些约束及阈值，
明确其与人工风格判断的边界；文风测试补充有依据的思考和机制解释可自然收尾的实例。
