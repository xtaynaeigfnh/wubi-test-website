# 文章语料写作契约

本目录是站点 300 篇打字练习正文的**唯一来源**。`scripts/generate-articles.mjs` 读取这里的
`short.mjs`、`medium.mjs`、`long.mjs`、`water.mjs`，校验后写出 `public/data/articles-*.json`
与 `public/data/articles-index.json`（`version` 为 3）。

## 为什么要重写

上一版正文由模板槽位拼装：12 个开头 × 12 个转折 × 12 个收尾按序号轮转，中间用抽象名词填空。
诊断结果（对旧 300 篇统计）：

- 548 个整句跨篇复用，单句最多同时出现在 15 篇里，例如“眼不见心不烦这话，在这儿不管用”“没什么惊天动地的结论”；
- 15 篇共用“谁也没多说，可谁都盼着它能自己好起来”，18 篇共用“挑了个平常的日子复查，能再次出现的改善才算数”；
- 结尾清一色格言式感悟（“道理不新鲜，做到不容易”“仅此而已”“如果只能留一句话”）；
- 长文平均 20 段、段长标准差仅 15 字，段落长度几乎相等，读起来像把同一篇作文拆碎洗牌；
- “真正”出现在 89 篇（30%），“反而”63 篇（21%），“不是……而是”58 篇（19%）；
- 全文几乎没有人名、地名、价格、次数、对话，读完什么信息都没留下。

所以正文改为人工写作，模板机器整体删除。**不要**用循环、占位符或句式池重新生成这些文字。

## 硬性规则

1. **一篇一个具体场景。** 每篇至少 2 个可核对的具体信息（时间、数量、价格、次数、尺寸、距离、
   楼层、年份……）和 1 件具体物品。分配表里给出的“细节要求”两项必须落到实处。
2. **要有对话。** short/medium/long 每篇至少 1 处直接引语，water 至少 2 处。引语使用中文引号
   `“”`，要像人说的话，允许“吧、嘛、哎、我说、你看”这类口语成分。
3. **结尾不许升华。** 禁止用格言、劝诫、对仗总结收尾，禁止“才是最重要的”“更值得”“本身就是”
   这类点题。按分配表指定的收尾方式结束：停在一个动作、一个数字、一句引语、一个画面、一件后来
   发生的小事，或者一个没有解决的问题。
4. **叙述者不要统一。** 可以用“我”，可以用分配表给的称呼，也可以不出现叙述者。同一批里
   “我们”最多 1 篇。
5. **句子长短要有落差。** 每篇至少 1 句不超过 8 字，至少 1 句不短于 35 字（long 至少 2 句）。
   不要每句都是二三十分字的均衡复句。
6. **段落长短也要有落差。** 最长段不短于最短段的 2 倍；long 允许单句成段。
7. **按分配表的“形态”写。** 不要把每篇都写成“现象—症结—做法—结果—体会”。允许一件事没办成、
   允许不给出结论、允许只写一个下午发生了什么。
8. **只用汉字和中文标点。** 不得出现 ASCII 字母或 ASCII 标点；数字、百分比一律写汉字
   （“三十二”“百分之八十五”“二〇二六年”）；不得出现连续标点（`，。`、`？？` 这类）；
   引号必须成对。
9. **长度**（去掉全部空白字符后的字符数，含标点）：
   | 长度 | 区间 | 目标 |
   | --- | --- | --- |
   | short | 80–180 | 145 左右 |
   | medium | 300–600 | 470 左右 |
   | long | 1000–1800 | 1300 左右 |
   | water | 400–900 | 620 左右 |
10. **篇内不得重复。** 不得出现相同整句（8 字以上），同一段 12 字以上文字不得重复 3 次。
11. **不要搬别的篇目的句子。** 开头和结尾最容易撞车：写之前先想清楚这篇的切入点是什么。
12. 不要议论“写作”“文章”“阅读者”本身，不要自我指涉。

## 黑名单

**生成脚本会直接报错的固定串**（不要写）：

```
道理不新鲜 说到底 仅此而已 不敢打包票 如果只能留一句话 眼不见心不烦 没什么惊天动地的结论
才是最重要的 更值得 本身就是一种 这次的经历 这次经历 由此可见 总的来说 在某种程度上
从某种意义上 不可否认 与此同时 值得注意的是 不难发现 可以看出 归根结底 换言之 换句话说
需要指出的是 日子照常 事情不大 眼不见为净
```

**每篇合计不超过 2 次**：其实、真正、反而、值得、往往、毕竟、或许、无疑、某种程度上。

**不要用的句式**：`让……变得……`、`让……重新……`、`使……成为……`、`为……留下……` 这类抽象
升华句（“让他先走”这种具体动作可以用）；`不是……而是……` 全篇最多 1 次，且不得出现在结尾句。

## 形态（按分配表执行）

| 代号 | 形态 | 说明 |
| --- | --- | --- |
| S1 | 现场白描 | 从一个具体动作或物品切入，不先给结论，全文把这件事写清楚 |
| S2 | 对话推进 | 用两三个人的对话写出分歧，叙述只做串联 |
| S3 | 时间线 | 按“某天—某天—后来”推进，写出过程与中间的反复 |
| S4 | 失败复盘 | 先写没成的那一次，再写第二次改了什么 |
| S5 | 两种做法对比 | 同一件事的两种做法并排写，不下判断 |
| S6 | 连续观察 | 记一段时间里的次数、时间、数字，让规律自己浮出来 |
| S7 | 步骤清单 | 把做法分步写出来，中途插一次意外 |
| S8 | 一问一答 | 有人问、有人答，再加一次追问 |
| S9 | 事后回访 | 过一段时间回头看，只写变化本身，不做总结 |
| S10 | 现场分歧 | 一件小摩擦，各人立场不同，最后怎么落地 |
| S11 | 数字对账 | 从一个对不上的数字开始，一直查到对得上 |
| S12 | 开放收尾 | 写到某个具体画面或一句没答完的话就停，不点题 |

## 范例

下面是**参考写法**，不要照抄内容，也不要把它当模板批量改写。

short（一到四段，150 字上下，停在一句引语上）：

> 打印机的出纸口又吐出半截表格。老陈把纸抽出来对着光看了看，没说话，翻开机盖把里面那沓又抖了一遍，还是少。第三次了，每次都得打三页以上。他给维修打电话，对方说下午来。下午来的是个年轻人，拆开侧盖，从进纸轮底下拈出一小片标签纸，上个月贴快递单时掉的。老陈盯着那片纸问：“就这东西？”年轻人说：“就这东西。”

medium（四段，段落长短不均，停在具体动作上）：

> 六月里，小林连着三天没找到那份报价单。文件名从“最终版”到“最终版二”，再到“真的最终版”，修改时间只差几分钟。
>
> 他去问负责归档的老周。老周把屏幕转过来，文件夹里躺着七份同名文件。“你发给客户的是哪一份？”老周问。小林答不上来。
>
> 两个人花了一个下午逐份比对金额，最后从下载目录里翻出发出去的那一份：总价比其余六份少两千八百块，是客户压过价的版本，另外六份都还留着旧价。
>
> 老周没让他装文件管理软件，只定了一条：文件名照“二〇二六年七月二十六日青禾报价单”这样写，日期在前，项目在后，不许出现“最新”两个字。小林当天把七份删到一份。第二天早上他打开文件夹，直接点开了最上面那一份。

long 的写法：8–16 段，至少 3 个不同时间点或场景，中间要有一次没成、一次改动、一次别人的意见，
不能靠反复描述同一个观察凑字数；结尾停在具体事件上，不做总结。

water（群聊答疑，≥4 段，≥2 处引语，停在一条新消息上）：

> 群里有人发了一张厨房秤的照片，说买回来的青菜少了差不多一两。底下立刻跳出来三种说法：秤不准、袋子含水、摊主手快。
>
> “你先换个东西称。”开超市的老魏回得最快，“拿一包没开封的盐，包装上写着多少就称多少。”

## 交付格式

每批的分配表在 `_parts/` 下。写完后把结果写成**一个 JSON 文件**，路径和文件名以分配表为准，
结构固定为：

```json
[
  { "id": "short-001", "title": "没有行动项的会议", "topic": "职场办公", "length": "short", "text": "第一段。\n\n第二段。" }
]
```

- `text` 里段落之间用 `\n\n`，不要有行首缩进，不要用 Markdown 标记。
- `title` 不超过 14 字，只用汉字，篇目之间不得重复。
- 写完必须自查长度：

```bash
node -e "const a=require('./scripts/article-corpus/_parts/s01.json');for(const x of a)console.log(x.id,x.title,x.text.replace(/\s/g,'').length)"
```

长度不在区间内、引语数量不够、或命中黑名单的，当场改掉再交。

## 最后一道自查

通读每一篇，把里面所有具体信息（时间、数字、名字、物品、谁说了什么）删掉，如果剩下的句子
放到任何一篇文章里都成立，那就删掉这句话——那正是“AI 味”的来源。
