# 五笔测试网站

一个面向 86 版五笔熟练用户的本地优先打字练习网站。它提供文章测速、节奏实验室、中文实战场、七日/十四日阶段目标、自适应今日训练、间隔复习、错题与卡顿片段复练、离线查码、周报与能力雷达、可解释的数据维护与完整本地备份，以及可跨页面持续播放的离线 Lo-fi 音乐。

内置文章库包含 300 篇原创练习文本：短文 120 篇、中篇 105 篇、长文 45 篇、网络聊天“水文”30 篇，覆盖日常生活、职场办公、科技数码、自然旅行、阅读随笔、历史文化和通俗科普等主题。

常用字练习提供前 100、前 500、中 500、后 500 和前 1500 五个范围。
默认按字频顺序练习，也可以在练习工具栏中点击“乱序”重新排列。

## 快速开始

需要 Node.js 22.13 或更高版本。克隆或解压项目后运行：

```bash
npm ci
npm run dev
```

然后打开终端显示的本地地址。需要模拟生产环境时，改用：

```bash
npm run build
npm run start
```

## 功能概览

- 离线文章库：按短文、中篇、长文和水文筛选；生成数据会检查篇幅、标点、唯一性和跨文章重复度。
- 文章测速：实时统计速度、击键、码长、字准、键准、回改、退格、选重、打词率、左右手使用、暂停和重打，并对比理论最小码长。
- 个人最佳幽灵赛：可在开练前挑战同篇文章的个人最佳或最近一次记录，进度条显示双方位置，实时差距可随时关闭，结算后按五段查看追回和丢失的时间并再次挑战。
- 码长教练：结算时展示最优分段、单字输入基准、理论下限和 3～5 个词组推荐机会，计算本次可能节省的按键数。
- 词组专项：将文章结算中反复出现的高价值词组汇入训练中心，按二字、三字和四字词组去重练习。
- 今日训练：保留每日字数、分钟和轮数目标，并根据近期记录生成可保存的三步处方；练习天数和字根区域轮换按用户本地自然日计算。
- 自适应处方：综合编码错误、卡顿、重复回改、掌握度和时间衰减，安排文章热身、弱项复练与字根收尾；支持换组、任务状态和完成总结。
- 间隔复习：统一安排单字、词组和卡顿片段的下次复习日期；到期项按逾期时间、错误严重度和预计收益排序，每天最多展示 12 项，也可暂缓到次日而不会永久隐藏。
- 卡顿片段复练：从文章结算或历史热力图直接进入三连练，比较三轮耗时和错误，达标后标记暂时掌握，也可加入当日独立加练队列。
- 错题复练：按错误次数和掌握度整理题目，连续答对后逐步提高掌握度。
- 五码根专项：按撇、捺、横、竖、折五区集中训练常用单字。
- 练习离开保护：训练中心的字根、复习和词组专项，以及字码挑战开始后，切换训练标签、点击站内链接、浏览器回退、刷新或关闭页面都会提示确认；成绩保存失败时必须先重试保存，不能直接离开。
- 成绩趋势：查看近 7 天、30 天或全部练习的速度与准确率曲线，以及文章完成度、最近练习的详细诊断和卡顿热力图。
- 周报与能力雷达：按自然周汇总速度、字准、键准、码长、打词和稳定性，与上周比较练习量和能力变化，识别新增或已掌握的弱项，并可下载本地 PNG 周报。六项能力分别按页面公开的固定区间归一化，缺少原始数据时不会补默认分。
- 节奏实验室：分别分析中文上屏节奏和物理五笔键位节奏，显示启动、波动、最快十字、卡顿恢复、同手与换手间隔，并从最慢位置生成三连复练。
- 中文实战场：提供日常、办公和文学三类纯中文任务，只使用常规中文标点，分别训练启动、连续准确输入和长文耐力。
- 阶段目标：从速度、字准、键准、码长、打词和稳定性中选择一项主目标，按首日基线生成观察区间，完成 7 日或 14 日训练；每个训练日需等本地日期变化后继续，基线、阶段与最终复测只在场景版本、正文指纹及评测条件一致时比较，并同时标出字准、键准和码长代价。
- 按键画像：按物理键位累计练习按键，显示键盘热力图、左右手均衡、键盘行、手指和五笔五区使用率。
- 数据管理：按成绩摘要、卡顿热力图、幽灵时间线、节奏曲线、词组机会和复习队列显示数量、估算体积与自动淘汰顺序；清理前预览影响，只移除所选大对象并保留趋势所需摘要。支持完整 JSON 备份、恢复版本与预计变化预览、无正文的轻量统计摘要，以及自定义 TXT 文章管理。
- 个性化设置：调整正文字号、默认文章长度、编码提示、按键音、自动下一篇，以及系统、浅色、深色、竹纸、青黛和自定义配色主题。
- 离线安装：支持 PWA，在线打开并完成缓存后可以从浏览器安装到桌面。
- 成绩卡：把文章或专项训练成绩保存为本地 PNG 图片。
- 离线音乐：通过根级播放器手动播放内置 Lo-fi 曲目，并在页面切换时保持状态；鼠标停留或键盘焦点位于播放器内部时，控制栏不会自动折叠。

### 码长与理论下限

“码长”是练习期间字母键数与正确输入字符数的比值。“理论下限”使用项目内置的 86 版码表，在单字和词组之间选择总键数最少的组合，并返回对应分段。标点、数字和拉丁字母不参与计算；如果文章中有汉字无法在码表中匹配，页面会显示“—”。网站无法可靠还原输入法的实际上屏分段，因此结算页统一称为“推荐机会”，不会断言用户错过了某个词组。

### 幽灵赛时间线

幽灵赛只为内置文章和已经保存、编号固定的自定义文章记录压缩进度时间线。时间线按若干字符保存一次累计有效用时，不保存逐次键盘事件；手动暂停和浏览器标签页处于后台的时间都会排除。每篇文章最多保留个人最佳与最近两条时间线，全部文章还设有总数量上限，以控制本机存储和备份体积。

幽灵记录会同时核对文章编号、版本和正文指纹。文章内容或版本改变后，旧成绩仍可作为历史摘要保留，但旧时间线不会再用于当前文章的挑战。没有可比较记录、练习常用字随机序列或关闭幽灵赛时，文章测速会正常退化为普通练习。实时领先/落后提示是本机偏好，可以关闭而不影响幽灵位置和赛后复盘。

### 静流进阶数据

节奏分析不会保存完整按键序列。每次成绩只保留汇总指标、最多三十二个压缩曲线点和最多三个弱节奏片段；暂停与浏览器处于后台的时间不会计入节奏间隔。系统最多保留最近一百二十次节奏曲线，总体积达到上限后先删除旧曲线，仍保留成绩摘要。

阶段目标只保存一个活动周期和最近六个结束摘要，每日明细通过成绩编号关联，不复制练习正文。目标可暂停、恢复或取消，已有成绩不会被删除；训练过程平均值只作观察，不代替同条件复测。样本不足时界面会明确提示不确定性；场景版本或正文指纹变化后，旧评测仅保留只读失效摘要。

## 使用前须知

- 支持 macOS、Windows 和 Linux。
- 需要安装 Node.js 22.13 或更高版本。
- 第一次安装依赖需要联网；安装并构建完成后，日常练习不需要联网。
- 文章、86 版五笔码表和页面资源均包含在本地文件中。
- 练习成绩、错题和设置只保存在当前浏览器，不会上传。
- 完整备份包含可选的压缩幽灵时间线；V0.5 之前导出的旧版备份仍可恢复。
- 数据用量估算、清理、迁移记录和轻量摘要导出全部在当前浏览器完成，不上传练习正文或逐键事件。
- 这是源码体验包，不能直接双击 HTML 文件运行，需要通过终端启动本地服务。

## 第一次启动

### 1. 安装 Node.js

如果电脑尚未安装 Node.js，请前往 [Node.js 官方网站](https://nodejs.org/)下载安装。

安装完成后打开终端，检查版本：

```bash
node -v
npm -v
```

`node -v` 显示的版本需要不低于 `v22.13.0`。

### 2. 进入项目目录

先解压收到的 ZIP 文件，再在终端进入解压后的 `wubi-test-website`（五笔测试网站）目录。

macOS 或 Linux 示例：

```bash
cd "/你的路径/wubi-test-website"
```

Windows PowerShell 示例：

```powershell
cd "C:\你的路径\wubi-test-website"
```

路径中有中文或空格时，请保留两侧引号。

### 3. 安装依赖

```bash
npm ci
```

此步骤第一次执行时需要联网，通常只需执行一次。

### 4. 构建网站

```bash
npm run build
```

构建成功后会生成本地运行所需的文件。

### 5. 启动网站

```bash
npm run start
```

终端出现本地地址后，用浏览器打开它。默认通常是：

```text
http://localhost:3000/
```

不要关闭正在运行服务的终端窗口。练习结束后，在终端按 `Ctrl + C` 停止服务。

## 以后再次启动

只要没有删除 `node_modules` 和 `dist` 目录，以后进入项目目录后通常只需执行：

```bash
npm run start
```

网站启动后不需要连接外网。

## 端口被占用

如果默认端口已被其他程序占用，可以换一个端口：

```bash
npm run start -- --port 4173
```

然后打开：

```text
http://localhost:4173/
```

## 数据保存位置

练习成绩、压缩幽灵与节奏曲线、阶段目标、弱项与错题、词组机会、间隔复习状态、数据维护记录、文章进度、按键画像、每日目标、训练处方、卡顿加练队列、自定义文本、音乐偏好和界面设置都保存在浏览器本地：

- 换浏览器后不会自动带过去。
- 清除浏览器网站数据后，本地记录也会被删除。
- 网站“本地成绩”页面的“清除练习数据与计划”会删除成绩、错题、文章进度、处方、复习队列与阶段目标；不会删除设置、自定义文章、按键画像或音乐偏好。
- 网站“设置”页面可以导出完整备份，并在另一浏览器中恢复。
- 多个人在同一台电脑上使用时，建议分别使用不同的浏览器用户资料。

### 备份和恢复

1. 打开“设置”页面，在“备份与恢复”中点击“导出完整备份”。
2. 网站会下载一个版本化 JSON 文件，其中包含全部受支持的本地数据。
3. 恢复时选择该 JSON 文件，先核对练习、错字和自定义文章数量，再确认覆盖当前浏览器的数据。

恢复操作只接受不超过 2 MB、由本网站生成且结构有效的版本化数据项，不会导入未知的浏览器存储键。同一备份中的文章进度必须按 `articleId` 保持唯一，重复记录会被拒绝且不会写入任何本地数据；旧版本地数据若已有重复文章进度，读取时会合并练习次数、最佳速度、完成状态和最近一次练习信息并自愈写回。如果写入中途失败，网站会回滚到恢复前的数据，避免留下只恢复了一部分的状态。

“导出完整备份”用于迁移或恢复本机数据，可包含自定义文章和压缩时间线。“导出轻量统计摘要”只保留汇总统计，不含练习正文、热力图、时间线或逐键事件，适合分享或长期归档，不能用来恢复网站状态。在“数据用量与清理”中执行清理前，页面会先显示影响项数与保留内容；确认后只移除选中的大对象，保留趋势所需的成绩摘要。

## 安装到桌面并离线使用

通过 GitHub Pages 或本地 HTTPS 地址打开网站后，进入“设置”页面：

1. 等待页面显示“离线缓存已启用”。
2. 点击“安装到这台设备”；如果按钮不可用，使用浏览器菜单中的“安装应用”或“添加到主屏幕”。
3. 首次缓存会包含全部页面、文章库和基础数据。完整五笔码表和音频等资源会在首次使用后缓存，约占用数 MB 空间。

浏览器可能只在 HTTPS 或本机地址上提供安装入口。离线缓存兼容部署在仓库子路径下的 GitHub Pages 地址；首次缓存完成前请不要断网。

## 常见问题

### 提示 `node: command not found` 或“无法识别 node”

Node.js 尚未正确安装。重新安装 Node.js 后，关闭并重新打开终端。

### `npm ci` 下载失败

确认电脑可以访问互联网，然后重新执行 `npm ci`。如果使用了代理，也需要确认终端的网络设置正常。

### 修改文件后页面没有变化

先按 `Ctrl + C` 停止服务，再重新构建和启动：

```bash
npm run build
npm run start
```

### 可以直接发送 `dist` 目录吗

不可以。`npm run build` 生成的 `dist` 是 Vinext 运行产物，仍需由 `npm run start` 启动；如果需要纯静态文件，应使用 `npm run build:pages`，产物位于 `out`，并通过 HTTP 服务或 GitHub Pages 发布，而不是直接双击其中的 HTML。

## 项目维护与验证

### 项目结构

- `app/`：Next.js 路由、React 组件和客户端核心逻辑。
- `public/`：PWA 文件、生成的数据、图标与离线音频。
- `tests/`：基于 `node:test` 的逻辑、内容、交互契约和渲染测试。
- `scripts/`：文章、常用字和五笔码表生成脚本。
- `third_party/`：可再分发的原始数据、作者信息与许可证。
- `worker/`、`db/`、`drizzle/` 和 `build/`：可选的 Sites/Cloudflare Worker 与 D1 构建支持。

### 质量检查

运行完整测试：

```bash
npm test
```

练习文章、常用字表与 86 版五笔码表均已打包在项目中，网站运行时不连接外部服务。
所有练习记录只保存在当前浏览器。

单独检查代码规范和类型：

```bash
npm run lint
npm run typecheck
```

`npm run typecheck` 会先刷新 Next.js 路由类型，再执行严格 TypeScript 检查，避免 Vinext 与 Next.js 共用 `.next/types` 时读到另一种构建残留的类型文件。`npm test` 会运行核心逻辑、卡顿复练、内容数据和界面契约测试，完成 Vinext 生产构建，再验证渲染结果；它不包含 ESLint 和 TypeScript 检查。提交或发布前应同时运行上面的三项命令。GitHub Pages 工作流只有在这三项全部通过后才会执行静态导出和部署。

重新生成 300 篇练习文章、常用字表、完整 86 版五笔码表和字码挑战码表：

```bash
npm run data:generate
```

文章生成器会同时更新 `articles-index.json` 与 short、medium、long、water 四组正文文件。修改生成逻辑后应提交所有重新生成的 JSON，并运行完整测试，避免篇幅越界、标点异常或文章内容过度重复。

## 部署方式

- `npm run build` 使用 Vinext 生成适合本地或 Sites/Cloudflare Worker 运行的构建，随后可用 `npm run start` 本地启动。
- `npm run build:pages` 使用 Next.js 生成 `out` 静态目录。仓库的 GitHub Actions 工作流会在 `main` 分支更新后完成质量检查、设置仓库子路径并部署到 GitHub Pages。
- PWA 清单、Service Worker、数据加载和音乐路径均会适配 GitHub Pages 的仓库子路径。
- 静态构建将 Turbopack 根目录固定为当前项目目录，可在包含中文或空格的路径下构建。

## 新增音乐

播放器从 `public/data/music-catalog.json` 读取版本化曲目目录，不在组件中写死曲目。
新增音乐时：

1. 把音频文件复制到 `public/audio/tracks/`。
2. 在 `public/data/music-catalog.json` 的 `tracks` 数组末尾添加一条记录。
3. 填写稳定且唯一的 `id`、曲名、作者、站内音频路径、MIME 类型、时长、许可和来源页面。
4. 在 `THIRD_PARTY_NOTICES.md` 中补充来源与许可，然后运行 `npm test`。

目录中的 `sources[].src` 只接受 `/audio/tracks/` 下的站内路径，以保证离线运行。
当前支持 `audio/mpeg`、`audio/ogg` 和 `audio/mp4`。目录数组顺序就是播放顺序；
新增曲目后需要重新构建并发布网站，但不需要修改播放器代码。
